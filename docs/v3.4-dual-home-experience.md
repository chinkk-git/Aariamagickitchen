# V3.4 Dual Home Experience — implementation contract

## Owner-approved scope (2026-10-25)
Implement a locally persisted Home Style selector in the Android APK. Keep **Classic Kitchen** as the initial default, and add **Magical Adventure** as an optional Home layout. Switch instantly without uninstalling, clearing user data, or changing recipe data.

### Settings and persistence
- Settings > My Home Style: Classic Kitchen / Magical Adventure, each with an accessible label and visual preview.
- Persist selection locally across restart, rotation, offline use, and in-place APK upgrade; default to Classic when no preference exists.
- Settings entry reachable from both Home layouts. Do not affect other app preferences.
- Both layouts use exactly the same underlying routes, recipes, favorites, planner, saved creations, and pantry.

### Magical Adventure Home
- Use the approved Aaria avatar and approved spinning-globe artwork from repository; do not substitute generated lookalikes or add a dog unless an approved asset explicitly contains it.
- Large readable title and colorful, sparkling Pinterest-inspired styling.
- Rotating illustrated activity carousel with four items: Spin My Week, Cook with Family, Cook with Friends, World Recipes. Swipe/arrow navigation; tapping any visible item opens its actual destination directly; accessible alternatives for gestures, reduced motion, and screen readers.
- Separate prominent interactive World Map globe; keep it visually distinct from carousel's World Recipes choice.
- Surprise Me interactive magical treasure chest: reveal a random eligible real recipe, with repeat/retry and direct recipe navigation. Respect child safety and available recipe catalogue; no timer.
- Three independently horizontally scrolling sections: New Recipes (real new recipes), What I Made! (actual persisted photos/creations, helpful empty state), Recipes Around the World (countries with available approved recipes only).
- Preserve persistent bottom navigation Home, All Recipes, World, My Creations, Magic Pantry; Android Back, portrait/landscape, EN-GB/PT-BR, age 8–10 readability.

### Boundaries
- Preserve approved 97-recipe baseline (95 originals + #096 Italy and #099 China). Remaining 13 international recipes stay out of the APK.
- Keep production root index.html / GitHub Pages unchanged. APK-first preview on separate branch; no merge or release without owner acceptance.
- Do not create a second installed application or require uninstall. Maintain existing signing/package compatibility for in-place upgrade, if build evidence supports it.
- Avoid repeated G3 cycles: focused static checks, settings persistence and navigation checks, and targeted phone/tablet screenshots; exact-head APK artifact with SHA-256 and package identity.

### Acceptance
1. Fresh install defaults to Classic; toggle to Magical; close/relaunch remains Magical; switch back remains Classic.
2. All four carousel destinations and globe work; Surprise Me only chooses real eligible recipes.
3. Three horizontal rails use actual data, correct empty states, and functional tap navigation.
4. No loss of existing saved data; 97 recipes unchanged; offline navigation works.
5. Correct bilingual labels, responsive portrait/landscape, touch targets, accessibility and reduced-motion behavior.
6. Present genuine screenshots and installable APK to owner for review before merge.

## V3.4 preview implementation

The preview source is isolated to `feature/v3.4-dual-home-experience` and is injected into the transformed Android WebView page by `tools/v3/attach-v34-dual-home.mjs`. The production root `index.html` is a build input and is not modified by this implementation.

- The existing Classic Home remains the default; the selected style is stored under the separate local key `aaria.v34.homeStyle`.
- Magical Adventure reuses the transformed approved avatar, world map/globe implementation, canonical recipe data, existing routes and profile state.
- Captured or selected recipe photos are stored locally in a separate IndexedDB store and can be displayed beside saved creations.
- A V3.4-specific GitHub Actions workflow builds a co-installable debug preview and runs focused phone portrait and tablet landscape checks. It does not run the full G3 matrix or publish a release.
- V3.4 preview builds use a stable, separate package ID, increasing version code and branch-scoped cached Android debug signer so preview-to-preview updates can retain local data without replacing the existing app. In-place upgrade compatibility with the production package and signer is **not claimed** by this preview.

**Evidence status:** Source checks passed locally; genuine Android build, device screenshots, package/certificate values, artifact link and focused device checks are pending the exact-head V3.4 GitHub Actions run. Preview signer continuity depends on its GitHub Actions cache; this does not establish production-signing compatibility. This document does not claim those pending results.
